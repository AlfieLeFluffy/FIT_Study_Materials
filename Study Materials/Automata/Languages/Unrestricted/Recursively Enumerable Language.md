The most free [[Formal Language|languages]] in the [[Chomsky Hierarchy]] that are generated by [[Unrestricted Grammar]] and accepted by [[Turing Machine|Turing Machines]]. 
## Defintion
We can say a [[Formal Language|language]] $L \subseteq \Sigma^*$ can be:
- **Recursively Enumerable** if there exists some [[Turing Machine|Turing machine]] $M$ such that $L = L(M)$.
- **Recursive** if there exists some [[Complete Turing Machine|complete Turing machine]] $M$ such that $L = L(M)$.
### Properties
Some properties tied to the definition are:
- If $M$ is a [[Complete Turing Machine|complete Turing machine]] then we can say that $M$ decides language $L(M)$.
- To each recursive language there exists a [[Turing Machine|Turing machine]] that decides it, meaning for each input string it stops or satisfies another accepting condition.
- A [[Turing Machine|Turing machine]] that accepts a recursively enumerable language $L$ stops for each $w \in L$, but for $w \not\in L$ can either stop or infinitely cycle.
- A class of languages accepted by a [[Turing Machine|Turing machine]] or in other words are recursively enumerable is identical with language class of type 0 from the [[Chomsky Hierarchy]].
## Properties
Some of the basic properties of recursively enumerable languages are:
- Class of recursive and recursively enumerable languages are closed to operations $\cup$, $\cap$, $.$ and $*$.
- Class of recursive languages are closed to operation complement, but recursively enumerable languages are not.
- If languages $L$ and $L'$ (complement) are recursively enumerable, then both are recursive.
- As a result of properties about for both $L$ and $L'$ there must always occur at least one of the following situations:
	- $L$ and $L'$ are recursive.
	- Neither $L$ and $L'$ are recursive.
	- One of these languages is recursively enumerable, but not recurrent and the other is not recursively enumerable.
## Decision Problems
A **decision problem** $P$ can be understood as a function $f_{P}$ with a field of values $\{ true, false \}$. Such problem is usually defined/specified by:
- Definition field $A_{P}$ represented by a [[Set|set]] of possible instances of problems (inputs) $a$.
- [[Set#Subset|Subset]] of instance $B_{P} \subseteq A_{P}$, $B_{P}=\{ p|f_{p}(p)=true \}$, for which the value $f_{P}$ is $true$.
In [[Formal Language]] theory, these instances of problems are [[Turing Machine Coding|encoded]] over a suitable [[Alphabet|alphabet]] $\Sigma$. In that case the problem $P$ is the naturaly defined/specified by language $L_{P}=\{ w \in \Sigma^*|w=\text{code}(p),p\in B_{P} \}$, where $\text{code}: A_{P} \to \Sigma^*$ is an injective function, that assigns to each instance of a problem a relevant input string that is independent of $f_{P}$.
### Decision Problems in Turing Machines
If $P$ is a problem specified [[Formal Language|language]] $L_{P}$ over [[Alphabet|alphabet]] $\Sigma$, then the problem is:
- **Decidable** if $L_{P}$ is a **recursive language**.
- **Non-Decidable** if $L_{P}$ is not even recursively enumerable language.
- **Partially Decidable** if $L(P)$ is **recursively enumerable language**.
From previous definitions it applies that any decidable problem is also partially decidable, but some non-decidable problems are not partially decidable.
