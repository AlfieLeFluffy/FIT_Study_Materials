Only one control flow that handles all processors. Each instruction is comprised of a field containing operation codes for each processor.
## Characteristics
Basic characteristics of VLIW are:
- Only one [[Program Counter]].
- Instructions are processed in sequence.
- Instructions that handle inter-processor communication contain information about sender, receiver, data size, etc. This information is generated by the compiler.
- The compiler organizes independent instructions into one long instruction word.
Advantages of this approach are:
- Simple [[Hardware]]
- Good scaling
Disadvantages of this approach are:
- Conditioned jumps
- Issues with dataflow (sharing of results between operations)
- Program size (high amount of NOPs)
- Issues with backwards compatibility
## Comparision
In comparison to [[Superscalar Processor|superscalar processors]] VLIW can be faster depending on the superscalar architecture. Against a static version, VLIW can do 3-6 instruction more (width, per cycle) without any conflicts as those are detected during compilation, but against a dynamic version that can do instructions out of order it cannot compare.
